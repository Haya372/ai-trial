# 仕様定義スキル

## 目的

PRDをもとに実装の詳細仕様と設計（ドメインモデル・DB設計・API設計）を作成し、PDMと合意する。

```text
PRD作成 → Issue作成 → [仕様定義 ← 今ここ] → sub-issue起票 → 詳細設計 → TDD実装 → PRレビュー → マージ
```

## 手順

### ステップ 1: PRDを読む

```bash
cat docs/prd/PRD-XXX-[機能名].md
```

- ゴール・要件・非目標・制約・成功指標を把握する
- 不明点はユーザー（PDM）に確認する

### ステップ 2: 仕様書を作成する

mainの最新から `docs/issue-<親Issue番号>-spec-<機能名>` ブランチを作成し、`docs/spec/template.md` をコピーして `docs/spec/SPEC-XXX-[機能名].md` を作成する。

- SPEC番号は既存ファイルの連番とする
- ステータスは `作成中` で開始する
- PRD参照・親Issue番号を必ず記入する
- 基本フロー・制約条件・エッジケースを埋める
- `write-document` スキルに従って書く

**重要: テンプレートにないセクションを追加してはならない。** 受け入れ条件・スコープ外などはIssue側で管理する。

### ステップ 3: 設計セクションを埋める

テンプレートの「設計」セクション（ドメインモデル・DB設計・API設計）を埋める。Claude Codeではこのステップを designer Agent に依頼する。

- 設計原則は `docs/guidelines/guidelines.md`、バックエンド設計指針は `docs/guidelines/design-guidelines.md` を参照する
- ドメインモデル: エンティティ・値オブジェクト・集約の境界と不変条件を決める。用語・ビジネスルールは `docs/domain/template.md` に沿って `docs/domain/[エンティティ名].md` に定義し、仕様書からリンクする
- DB設計: テーブル名・カラム名・型・制約・インデックス・リレーションを決める（カラムの値が固定長の場合は `CHAR` を使う）
- API設計: エンドポイント・リクエスト・レスポンス・エラー種別とHTTPステータスを決める。あわせて、基本フローの操作ごとのAPI呼び出し順序と、レスポンスのどの値を次の呼び出しに使うかを決める
- 既存の承認済みADR（`docs/adr/`）と矛盾しないか確認する。既存ADRでカバーされない技術判断があれば、選択肢とトレードオフを仕様書と合わせてPDMに提示し、合意後にADRを作成する

### ステップ 4: PDMにレビュー・合意を依頼する

作成した仕様書の内容をユーザーに提示し、以下をまとめて1回で確認する。

- 基本フローはPRDのゴールを満たしているか
- 制約条件・エッジケースに抜けがないか
- ドメインモデル・DB設計・API設計（呼び出しシーケンスを含む）が仕様を満たしているか
- 新規ADRが必要な技術判断（ある場合）

フィードバックを受けたら仕様書を修正し、再確認を依頼する。

### ステップ 5: 合意後にステータスを更新し、PRを作成する

PDMの合意が得られたら、確認を挟まずに以下を続けて行う。

- ステータスを `PDM合意済` に更新し、合意日を記入する
- `commit` スキルでコミットし、`create-pr` スキルでPRを作成する
- PRのURLを伝え、マージを依頼する

### ステップ 6: sub-issue起票へ引き継ぐ

仕様書のPRがマージされたら、`create-sub-issue` スキルで親Issueを分割する。

- 引き継ぎ情報: 仕様書のパス・親Issue番号

---

## 仕様変更時のルール

仕様変更が発生した場合は以下を必ず行う。

1. 仕様書を更新する（更新日を記入する）
2. 変更内容をPRの本文またはコメントに記録する
3. PDMに再確認・合意を得る

## 実装完了後のルール

実装のPRがマージされたら：

1. 仕様書のステータスを `アーカイブ` に更新する
2. PR番号を仕様書に記入する

## チェックリスト

- [ ] PRDのゴール・要件をすべて把握したか
- [ ] 基本フロー・制約条件・エッジケースが記述されているか
- [ ] ドメインモデル・DB設計・API設計が記述され、既存ADRと矛盾していないか
- [ ] 基本フローの各操作に対応するAPI呼び出しシーケンスが記述されているか
- [ ] PDMの合意が得られたか
- [ ] 仕様書がPRとしてマージされたか
