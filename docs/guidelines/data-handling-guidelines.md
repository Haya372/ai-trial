# 情報取り扱いガイドライン

バックエンドが扱う情報の、DBへの保存方法と、APIレスポンス・ログ・トレースに出してよい情報を定める。

---

## 情報の分類

| 分類 | 具体例 |
|---|---|
| 識別子 | `user_id`・`event_id` などのID、`request_id`、ルートパターン |
| 認証情報 | パスワード、APIキー、セッションID、Bearerトークン、共有トークン |
| 個人情報 | メールアドレス、氏名、住所、電話番号 |
| ユーザーが入力した内容 | 予定の `title`・`description`・`location`・`url`、タグ名 |
| 内部実装の詳細 | SQL文、バインド値、テーブル名、DBエラーメッセージ、ファイルパス、ライブラリ名・バージョン、スタックトレース |

## DBへの保存

| 情報 | 保存方法 | 理由 |
|---|---|---|
| 識別子・個人情報・ユーザーが入力した内容 | 平文で保存する | 検索・一意制約・画面表示に元の値を使うため |
| パスワード | bcryptでハッシュ化して保存する | 人が決めるため推測しやすい。DBが漏洩しても総当たりを遅らせられる低速なハッシュを使う |
| アプリが発行するトークン（セッション・共有トークン） | `crypto/rand` で生成した32バイトの値とし、SHA-256ハッシュだけを保存する。平文はCookie・レスポンスで一度だけクライアントに渡す（[ADR-028](../adr/ADR-028-event-share-token.md)・[ADR-033](../adr/ADR-033-session-token-hashing.md)） | DBが漏洩してもなりすましに使えないようにするため。256bitのランダム値で総当たりが現実的でないため、SHA-256で足りる |
| アプリが元の値を使う秘密（APIキー・外部サービスの認証情報） | DBに保存せず、シークレットマネージャーで管理する。アプリへは実行環境がシークレットマネージャーから環境変数に注入して渡す。ローカル開発では本物の秘密を扱わず、ダミー値を使う | DBが漏洩しても秘密が漏れないようにするため |

アプリが元の値を使う秘密をDBに保存する必要が出た場合は、暗号化して保存する。暗号方式と鍵の管理方法はADRで決める。

## 出力先ごとの扱い

| 分類 | APIレスポンス | ログ・トレース | 理由 |
|---|---|---|---|
| 識別子 | API仕様で定義したものだけ出す | 出す | 障害調査で対象を特定するのに使う。値だけでは個人や内容を特定できない |
| 認証情報 | 本人に発行するトークン・Cookieだけ出す | 出さない | 漏れるとなりすましに使われる |
| 個人情報 | 本人のものだけ出す | 出さない。`user_id` を出す | ログ収集基盤や外部のトレースバックエンドに転送され、本番データへのアクセス権を持たない人も閲覧できる |
| ユーザーが入力した内容 | API仕様で定義したものだけ出す | 出さない。対象のIDを出す | 個人情報と同じ |
| 内部実装の詳細 | 出さない | 「内部実装の詳細の扱い」に従う | レスポンスは外部に届き、攻撃の手がかりになる |

### 内部実装の詳細の扱い

| 情報 | ログ・トレースでの扱い | 理由 |
|---|---|---|
| SQL文・バインド値 | 出さない | バインド値に個人情報やユーザーが入力した内容が入る |
| DBエラーメッセージ | `err.Error()` 経由で出してよい。値を含む `PgError.Detail` は出さない | 障害調査に使う。pgxの `PgError.Error()` はSQL文を含まず、値は主に `Detail` に入る。ただし型変換エラー（SQLSTATE 22P02・22007など）では `Message` に入力値が入るため、該当SQLへ渡す値は事前にアプリ側で検証する |
| スタックトレース | panicを回復した箇所でだけ、ERRORログの `stack` フィールドに出す | 通常のエラーは `fmt.Errorf` によるラップで発生経路がエラー文字列に残る（[オブザーバビリティガイドライン](observability-guidelines.md) の「エラーログは末端で1回だけ出す」）。panicはラップされずに伝播するため、スタックトレースでしか発生箇所を追えない |

## エラーをラップするときの文脈

ラップしたエラー文字列は、そのままログの `error` フィールドとスパンのステータスに入る。
`fmt.Errorf` で付与する文脈は識別子だけにする。

```go
// NG: 個人情報がエラー文字列経由でログに出る
return nil, fmt.Errorf("user_repository.find_by_email email=%s: %w", email, err)

// OK: 識別子だけを付与する
return nil, fmt.Errorf("user_repository.find_by_id id=%s: %w", id, err)
```
