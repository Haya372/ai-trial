# フロントエンド レビュー観点

## コンポーネント設計

`docs/guidelines/design-guidelines.md` のUIコンポーネント設計方針に沿っているか確認する。

- コンポーネントは単一責任か（表示・ロジック・データ取得を混在させていないか）
- Presentational と Container が適切に分離されているか
- コンポーネントが再利用可能な粒度になっているか
- コンポーネントが `className` をPropsとして外部公開していないか（`docs/guidelines/component-guidelines.md` 参照: variantで制御する）

## 状態管理

- 状態のスコープが適切か（必要以上に広いスコープで状態を持っていないか）
- 派生状態を `useState` で管理していないか（`useMemo` や算出プロパティを使うべき）
- 状態の不変性が保たれているか（直接ミューテーションをしていないか）

## 型安全性

- 外部APIレスポンスに型定義があるか（OpenAPIコード生成を使っていない場合）
- `null` / `undefined` の考慮漏れがないか（Optional Chaining・null合体演算子の使用）
- ジェネリクスが適切に使われているか

## パフォーマンス

- 不必要な再レンダリングが発生していないか（メモ化の欠如・依存配列の誤り）
- `useEffect` の依存配列が正確か（不足・過剰どちらも問題）
- 大きなリストにバーチャライズ（仮想化）が必要か検討されているか
- 重い処理が `useMemo` / `useCallback` でメモ化されているか

## アクセシビリティ

- インタラクティブ要素（ボタン・リンク）に `aria-label` またはテキストコンテンツがあるか
- フォーム要素に `label` が関連付けられているか
- セマンティックなHTML要素が使われているか（`div` のクリックイベントより `button` を使うべき）
- キーボード操作（Tab・Enter・Escape）が機能するか

## エラー・ローディング処理

- データ取得中のローディング状態が表示されるか
- エラー時のフォールバックUIがあるか
- エラー境界（Error Boundary）が適切に配置されているか

## スタイリング

`docs/guidelines/component-guidelines.md` のvariantルールに沿っているか確認する。

- コンポーネントの見た目が `variant` / `size` Props経由で制御されているか（classNameの直接上書き禁止）
- グローバルCSSを汚染していないか（スコープが適切か）
- レスポンシブ対応が考慮されているか
- ハードコードされた色・サイズ値がデザイントークンに置き換えられているか
