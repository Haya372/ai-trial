# ドキュメント レビュー観点

## 正確性

- コードの実装内容とドキュメントの記述が一致しているか
- コマンド・設定値・ファイルパスが実際のものと合っているか
- APIの仕様（パラメータ・レスポンス）が実装と一致しているか
- 既存のドキュメントへの参照先（リンク・ファイルパス）が正しいか

## 完全性

- 必須セクションがテンプレートに従って記述されているか
- 「やること」が全て記述されているか（手順の途中で終わっていないか）
- 前提条件・必要な環境が記述されているか
- エラー時の対処方法が記述されているか（手順書・運用ドキュメントの場合）

## 明瞭さ

- 専門用語・略語に初めて登場する箇所での説明があるか
- コードサンプルが動作するか（コピー＆ペーストで実行できるか）
- 図表が内容を正確に表しているか
- 曖昧な表現（「適切に」「必要に応じて」）が具体的に書き直されているか

## 書式・一貫性

- Markdownの記法が正しく使われているか（見出しレベル・コードブロックの言語指定）
- プロジェクト内の他ドキュメントと用語・表記が統一されているか
- 日本語/英語の表記が混在していないか（本プロジェクトの規約に従っているか）
- テーブルのカラム幅・アライメントが整っているか

## 鮮度・メンテナンス性

- 古いバージョン・廃止された設定への言及がないか
- 「TODO」「後で追記」のような未完成のメモが残っていないか
- ADR・仕様書の場合、ステータス・日付が記入されているか
- 変更内容がIssue/PRへの参照・背景説明と共に記述されているか（ADRの場合）
