# PRD-012 SSOログイン

- 作成日: 2026-11-23
- 更新日: 2026-11-23

## 概要

外部のIDプロバイダー（以下、IdP）のアカウントでアカウント登録・ログインできる機能。メールアドレス + パスワードで登録済みのユーザーは、本人確認のうえ既存のアカウントにIdPのアカウントを連携できる。

## 背景

現在のログイン手段はメールアドレス + パスワードだけで、ユーザーはこのサービス専用のパスワードを作って覚えておく必要がある。パスワードを忘れるとログインできなくなり、覚えやすい弱いパスワードや他サービスとの使い回しは不正ログインの原因になる。
普段使っているIdPのアカウントでログインできれば、ユーザーはこのサービス用のパスワードを管理しなくて済む。

## 目標

- IdPのアカウントだけで、パスワードを作らずにアカウント登録・ログインできる
- メールアドレス + パスワードで登録済みのユーザーも、同じアカウントのままSSOでログインできる

## 非目標

- 組織ごとに社内IdPを設定する企業向けSSO
- 連携したIdPアカウントの解除・付け替え
- IdPが提供する他サービス（カレンダーなど）とのデータ連携

## ユーザーストーリー

- さくらとして、普段使っているIdPのアカウントでワンクリックで登録したい。なぜなら、新しいパスワードを考えて覚えるのが面倒だから
  - 受け入れ条件: ログイン画面の「SSOでログイン」からIdPで認証すると、パスワードを入力せずにアカウントが作成され、カレンダーが表示される
- 拓也として、すでにメールアドレスで登録したアカウントのまま、SSOでもログインしたい。なぜなら、登録済みの予定をそのまま使い続けたいから
  - 受け入れ条件: 登録済みと同じメールアドレスのIdPアカウントでログインすると、既存のパスワードを1回入力するだけで連携され、以降はSSOだけでログインでき、既存の予定が表示される

## 要件

### 機能要件

- ログイン画面・アカウント登録画面に「SSOでログイン」を表示すること
- IdPアカウントのメールアドレスが未登録の場合、IdPでの認証だけでアカウントを作成しログインさせること
- IdPアカウントのメールアドレスが、メールアドレス + パスワードのアカウントとして登録済みの場合、既存のパスワードを入力させて本人確認し、成功したらIdPアカウントを既存のアカウントに連携してログインさせること
- 連携済みのアカウントは、SSOとメールアドレス + パスワードのどちらでもログインできること
- SSOで作成したアカウントにメールアドレス + パスワードでログインしようとした場合、「SSOでログイン」を使うよう案内すること
- IdPでの認証をユーザーがキャンセルした場合、ログイン画面に戻すこと

### 非機能要件

- IdPでの認証を終えてサービスに戻ってから、カレンダーが表示されるまで3秒以内であること

## 制約

- IdP側でメールアドレスが確認済みのアカウントだけを受け付ける
- 連携時の本人確認でのパスワード誤入力も、アカウントロック（PRD-011）の失敗回数に含める

## 成功指標

- IdPでの認証に成功してサービスに戻ったリクエストの99%以上で、ログイン（または連携画面の表示）まで完了すること
