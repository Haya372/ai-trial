# ADR-017: フロントエンドコード品質ツールの役割分担

- ステータス: 承認済

## コンテキスト

`apps/web` のフロントエンドでは Biome・oxlint・knip の3ツールが導入されているが、
ルートの `biome.jsonc` で linter/formatter が両方 `enabled: false` になっており、
Biome の使用有無と各ツールの役割分担が不明確だった。

## スコープ外

- バックエンドのコード品質ツール選定
- ツール自体のバージョンアップ方針

## 決定

Biome をフォーマッター専用として継続使用する。リンターは oxlint が担当し、
未使用コード検出は knip が担当する。

| ツール | 役割 |
|---|---|
| Biome | フォーマッター・import 整理 |
| oxlint | リンター（lint ルール適用） |
| knip | 未使用コード・依存関係の検出 |

## 検討した選択肢

### 選択肢1: Biome をフォーマッターとして継続使用（採用）

#### 概要

Biome のリンターは無効のまま、フォーマッターと import 整理のみ利用する。
リンターは引き続き oxlint が担当する。

#### メリット

- 現状の CI・スクリプトへの変更が最小限
- oxlint は Biome より高速でルールセットも充実している
- Biome のフォーマッターは TypeScript/CSS の統合フォーマットとして機能している

#### デメリット

- ツールが3つに分散しており、役割を把握する必要がある

### 選択肢2: Biome を廃止し Prettier + oxlint + knip に移行

#### 概要

Biome を削除し、フォーマッターを Prettier へ変更する。

#### メリット

- Prettier は実績が多く設定が豊富

#### デメリット

- Prettier への移行コストが高い（設定・CI・既存ファイルの再フォーマット）
- すでに Biome フォーマッターが機能しており移行メリットが薄い

### 選択肢3: Biome と oxlint を併用（linter を両方有効化）

#### 概要

Biome のリンターを有効化し、oxlint と並行して実行する。

#### メリット

- 両ツールのルールセットを組み合わせてより広くカバーできる

#### デメリット

- ルールが重複し、同じ違反が二重に報告される
- どちらのツールで設定を管理すべきか曖昧になる
- CI で2つのリンターを実行するため余分な時間がかかる

### 選択肢4: Biome に一本化（linter/formatter 両方有効化）

#### 概要

oxlint を廃止し、Biome のリンターとフォーマッターを両方有効化する。

#### メリット

- ツール数を削減できる

#### デメリット

- oxlint の方が Biome リンターより高速かつルールが充実している
- 既存の oxlint 設定を Biome に移植するコストが高い

## 決定理由

oxlint はすでに CI で機能しており、Biome リンターへの移行コストに対するメリットがない。
Biome フォーマッターも CI で稼働済みのため現状維持が最適。

## 結果

### 良い影響

- 各ツールの役割が明確になり、設定の意図が把握しやすくなる
- CI・スクリプトへの変更なしで混乱を解消できる

### 悪い影響

- 3ツール構成のため、新規参加者がツールの役割を把握する必要がある
