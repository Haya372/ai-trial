# ADR-021: フロントエンドライブラリ選定（ルーティング・フォーム管理・バリデーション）

- ステータス: 承認済

## コンテキスト

ADR-007でフロントエンドの状態管理として TanStack Query + Zustand を採用したが、以下の3点はユーザー認証機能（PRD-001）の詳細設計時に決定すると明記されていた。

- ルーティングライブラリ
- フォーム管理ライブラリ
- バリデーションライブラリ

ユーザー認証機能では、ログイン・サインアップページへのルーティング・未ログイン時のリダイレクト・フォーム入力のバリデーションが必要になる。これらの実装に先立ち、使用するライブラリを決定する。

## スコープ外

- SSR・SSGを前提とするルーティング設計
- フォーム以外のUI状態管理（ADR-007でZustandを選定済み）
- サーバーサイドバリデーションライブラリの選定（バックエンドはGo標準の実装を使用）

## 決定

以下の3ライブラリを採用する。

| 用途 | ライブラリ |
|---|---|
| ルーティング | TanStack Router |
| フォーム管理 | React Hook Form |
| バリデーション | zod |

## 検討した選択肢

### ルーティング

#### 選択肢1: TanStack Router（本決定）

##### 概要

TypeScriptファーストのルーティングライブラリ。ルートパラメータ・検索パラメータ・ローダーの型がすべてコンパイル時に保証される。

##### メリット

- パスパラメータ・検索パラメータが型安全で、型推論が自動で効く
- ADR-007で採用済みのTanStack Queryと同じエコシステムで、ローダーとの統合が素直に書ける
- 未ログイン時リダイレクトをルート定義の `beforeLoad` フックで型安全に実装できる

##### デメリット

- React Routerに比べて実績・学習リソースが少ない
- ファイルベースルーティングを使う場合はコード生成ステップが必要

#### 選択肢2: React Router v7

##### 概要

Reactのルーティングライブラリの業界標準。v7でフレームワークモード（SSR対応）とSPAモードが統合された。

##### メリット

- 最も普及しており、学習リソース・コミュニティが最大
- Remix由来のローダー・アクションパターンが組み込まれており、データフェッチとの統合が容易

##### デメリット

- 型安全性はTanStack Routerに劣り、パスパラメータはstring型になることが多い
- TanStack Queryとの二重のデータ取得パターンが混在しやすい

### フォーム管理とバリデーション

#### 選択肢1: React Hook Form + zod（本決定）

##### 概要

React Hook Formはアンコントロールドコンポーネントベースのフォームライブラリ。zodはTypeScriptファーストのスキーマバリデーションライブラリ。`@hookform/resolvers` でzodスキーマをReact Hook Formに統合できる。

##### メリット

- 不要な再レンダリングが少なく、フォームのパフォーマンスが高い
- zodスキーマはフォームバリデーションとAPI型定義の双方に使い回せる
- 業界で最も普及しており、学習リソースが豊富
- zodは `orval`（ADR-016）との統合が容易で、OpenAPIスキーマから型を生成する際にも利用できる

##### デメリット

- アンコントロールドコンポーネントの仕組みを理解するまで学習コストがある
- シンプルなフォームに対して設定量がやや多い

#### 選択肢2: conform + zod

##### 概要

サーバーサイドバリデーションとの統合を重視したフォームライブラリ。React Server ActionsやRemix Actionと親和性が高い。

##### メリット

- クライアントとサーバーで同じzodスキーマを使い回せる設計

##### デメリット

- 本プロジェクトはSPA構成でServer Actionsを使わないため、conformの主要な強みが活かせない
- React Hook Formに比べてエコシステム・学習リソースが少ない

## 決定理由

- **TanStack エコシステムの統一**: ADR-007でTanStack Queryを採用しており、TanStack Routerと組み合わせることで型安全なルーティング・データフェッチが一貫したAPIで書ける。型安全性はReact Routerに明確に優位
- **型安全な認証ガード**: TanStack Routerの `beforeLoad` を使った未ログイン時リダイレクトは、型安全にコンテキストを受け渡せる。React Routerのカスタムコンポーネントによるガードに比べてボイラープレートが少ない
- **React Hook Form + zodの普及率**: 認証フォームはフィールド数が少なく、パフォーマンス上の優位性よりも学習コストの低さが重要。最も普及しているこの組み合わせを選ぶことでチームへの導入コストを最小化できる
- **zodの横断利用**: zodスキーマはフォームバリデーション・API型（orvalで生成するスキーマ）の双方で活用できる。バリデーション定義を一箇所に集約できる

## 結果

### 良い影響

- ルートパラメータ・検索パラメータがコンパイル時に型保証され、存在しないルートへのリンクをビルド時に検出できる
- 未ログイン時リダイレクトをルート定義に集約でき、ページコンポーネントが認証状態を意識しなくてよくなる
- zodスキーマをフォームバリデーションとAPI型定義で共有でき、バリデーションルールの重複定義がなくなる

### 悪い影響

- TanStack Routerはファイルベースルーティングを使う場合にコード生成（`tsr generate`）の実行が必要になる
- React Routerに比べて学習リソースが少なく、ドキュメント参照コストがある
