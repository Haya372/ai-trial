# ADR-027: カレンダー描画ライブラリの選定

- ステータス: 承認済

## コンテキスト

ADR-005（フロントエンドフレームワーク）と ADR-015（コンポーネントライブラリ）の両方で「カレンダー描画に外部ライブラリを利用するかどうかの判断は詳細設計時に決定する」と明記されていた。

Issue #19（PRD-002: カレンダービュー）の詳細設計にあたり、月ビュー・週ビューを実装するためのカレンダー描画ライブラリを選定する必要がある。

仕様書 SPEC-002 で定義されたエッジケース（複数日にわたる予定の横断ブロック表示・終日予定の専用エリア・同時間帯複数予定の横並び）はいずれも実装難易度が高く、外部ライブラリの採用可否が実装コストに大きく影響する。

## スコープ外

- 日ビュー（PRD-006 今日のタイムラインで別途対応）
- 印刷・エクスポート機能
- ドラッグ&ドロップによる予定の移動・リサイズ（このIssueのスコープ外）
- カレンダーライブラリへの TanStack Query との直接統合方法（実装詳細）

## 決定

カレンダー描画ライブラリとして **FullCalendar**（@fullcalendar/react + @fullcalendar/daygrid + @fullcalendar/timegrid）を採用する。

`packages/ui` にラッパーコンポーネントを設けて FullCalendar への直接依存を閉じ込め、アプリケーション層は `packages/ui` のラッパー経由でのみ利用する。

## 検討した選択肢

### 選択肢1: FullCalendar（採用）

#### 概要

オープンソースのカレンダーUIライブラリ。React バインディング（@fullcalendar/react）を提供し、月ビュー（daygrid）・週ビュー（timegrid）を標準プラグインとして持つ。基本機能は MIT ライセンス。

#### メリット

- 月ビュー・週ビューが標準プラグインとして実装済みで、SPEC-002 の全要件（複数日予定の横断ブロック・終日予定の専用エリア・同時間帯複数予定の横並び）を追加実装なしに満たす
- React バインディングが公式提供されており、ADR-005 の React 採用と整合する
- v6 系が活発にメンテナンスされており、長期的なサポートが期待できる
- `packages/ui` のラッパーパターン（ADR-015）で内部に閉じ込め、アプリケーション層に FullCalendar の API を露出しない設計が可能

#### デメリット

- バンドルサイズが大きい（gzip 後 約 150kB）
- ラッパーを経由した Tailwind CSS によるスタイリングの上書きに工夫が必要

### 選択肢2: react-big-calendar

#### 概要

React 向けのカレンダーコンポーネントライブラリ。月ビュー・週ビュー・日ビューを標準サポートし、MIT ライセンス。

#### メリット

- FullCalendar に比べてバンドルサイズが小さい（gzip 後 約 50kB）
- MIT ライセンスで利用制限なし

#### デメリット

- メンテナンスが低調で、最終リリースが長期間更新されていない期間があった。長期的なサポートリスクが高い
- TypeScript 対応が FullCalendar に比べて弱く、型定義の精度が低い
- 複数日にわたる予定の横断表示・終日予定エリアの挙動が FullCalendar に比べて不安定なケースが報告されている

### 選択肢3: カスタム実装（CSS Grid + JavaScript）

#### 概要

外部ライブラリを使わず、CSS Grid と JavaScript で月ビュー・週ビューを自前実装する。

#### メリット

- バンドルサイズへの影響が最小
- デザインシステム（Tailwind CSS）との完全な統合が可能
- 外部ライブラリへの依存がない

#### デメリット

- SPEC-002 のエッジケース（複数日予定の横断ブロック・終日予定エリア・同時間帯複数予定の横並び・週またぎ処理）をすべて自前実装する必要があり、実装コストが極めて高い
- テスト・バグ修正のコストが外部ライブラリ利用時に比べて大幅に増加する
- YAGNI 原則（ADR-001 設計ガイドライン）に反して、既存ライブラリで解決できる問題を自前実装することになる

## 決定理由

- **SPEC-002 要件の網羅性**: 複数日予定の横断ブロック・終日予定専用エリア・同時間帯複数予定の横並びはいずれも実装難易度が高い。FullCalendar はこれらすべてを標準機能として提供し、カスタム実装のリスクを排除できる
- **メンテナンスリスク**: react-big-calendar はメンテナンスが低調であり、長期運用での追従コストが懸念される。FullCalendar v6 は活発にメンテナンスされている
- **ADR-015 との整合**: `packages/ui` のラッパーパターンで FullCalendar 依存をAdapter 層に閉じ込めることで、アプリケーション層は FullCalendar の API を意識しない設計にできる。将来的な差し替えも可能
- **バンドルサイズ**: 約 150kB（gzip）は許容範囲であり、週/月ビューの表示性能（1秒以内）はキャッシュ設計で対応する

## 結果

### 良い影響

- SPEC-002 のエッジケース（複数日予定・終日予定・重複予定の表示）を追加実装なしに満たせる
- `packages/ui` のラッパーにより、FullCalendar の API 変更の影響をラッパー層だけに閉じ込められる
- FullCalendar の月/週ビューがアクセシビリティ（キーボードナビゲーション・ARIA）を標準でサポートしている

### 悪い影響

- バンドルサイズが増加する（gzip 後 約 150kB）
- Tailwind CSS によるスタイリングの上書きには CSS カスケードの制御が必要になる
- ラッパー設計のコストが生じる（ただし、実装コスト削減のトレードオフとして許容）
