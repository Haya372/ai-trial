# PR 作成スキル

## 目的

GitHubのPRをテンプレートに準拠した形で作成する。
レビュアーが変更の背景・影響範囲を素早く把握できる情報を揃えることが目的。

---

## 手順

### ステップ 1: 情報を準備する

- 対応するIssue番号
- 変更内容のサマリー（1〜3点）
- 背景・コンテキスト（なぜこの変更が必要か、意思決定の経緯）
- リスク・影響範囲（既存機能への影響、ロールバック方法など）

### ステップ 2: PR作成コマンドを実行する

```bash
gh pr create \
  --title "<type>: <タイトル>" \
  --body "$(cat <<'EOF'
## 概要

<変更内容の簡潔な説明>

## 関連Issue

Closes #<Issue番号>

## 背景・コンテキスト

<なぜこの変更が必要か。意思決定の経緯や前提条件>

## 変更内容

- <主な変更点1>
- <変更点2>

## リスク・影響範囲

<既存機能への影響・注意点・ロールバック方法など（なければ「なし」）>

## チェックリスト

- [ ] 関連するIssueに紐づいている
- [ ] 設計ドキュメントのインターフェースと実装が一致している
- [ ] コードコメントはWHYのみ書かれている
EOF
)"
```

---

## チェックリスト

- [ ] テンプレートの全セクションが埋まっているか
- [ ] タイトルがコミットメッセージ規約に沿っているか（`feat:` / `fix:` / `chore:` など）
- [ ] Issue番号が正しく参照されているか
