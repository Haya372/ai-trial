# Retrospective スキル

## 目的

セッション中に発生した問題を振り返り、再発防止のための改善アクションを導き出す。
振り返りの結果はスキルの更新・CLAUDE.mdへの追記・開発フローの見直しに繋げる。

---

## ワークフロー

### ステップ1: 事象の洗い出し

会話を振り返り、以下の観点で問題を列挙する。

- エージェントが途中で止まって確認を求めた
- 同じ種類の操作に対して承認を繰り返し求められた
- 指示と異なる出力（言語・形式・内容）が生成された
- 手戻り・修正が発生した
- 想定より多くのターンを要した

---

### ステップ2: 根本原因の分類

各問題の原因を以下のカテゴリに分類する。

| カテゴリ | 意味 | 対策の方向性 |
|---|---|---|
| **ツールで防げる** | lint・静的解析・hookで自動検出できた | linter/hook設定を追加・強化する（最優先） |
| **スキル不足** | スキルに記載がなかった・曖昧だった | スキルを更新する |
| **スキル未参照** | スキルがあるのに参照されなかった | descriptionや呼び出し条件を改善する |
| **指示の曖昧さ** | ユーザーの指示が不明確だった | CLAUDE.mdに補足する・質問する |
| **エージェントの判断** | スキル・指示に関係なく発生した | スキルに明示的な禁止事項を追加する |
| **承認の繰り返し** | 同じ操作への承認が頻発した | 許可リストへの追加 or スクリプト化 |

> **原則**: ツールで防げる問題はツールで防ぐ。スキルへの注意書きは人間（エージェント）の記憶に依存するが、lint・hook・静的解析は忘れない。まず「自動化で解決できないか」を検討してからスキル更新に進む。

---

### ステップ3: 改善アクションの策定

各問題に対して具体的なアクションを決める。**まず「ツールで防げるか」を検討する。**

#### ツールで防ぐ場合（最優先）

問題が「チェックすれば気づけた」類のものは、自動化で根本解決する。

- **linter/静的解析の追加**: golangci-lint ルール追加、ESLint ルール追加など
- **pre-commit hook**: フォーマット・型チェックなど高速なチェックを追加（`lefthook.yml` の `pre-commit`）
- **pre-push hook**: build・lint など少し重いチェックを追加（`lefthook.yml` の `pre-push`）
- **CI チェックの追加**: ローカルで再現しにくいチェックはCIに追加

ツールでの対応が完了した後、補足的にスキルへの記載が必要かを判断する。

#### スキルを更新する場合

- 何を追記・修正するか（あいまいな表現の強化、禁止事項の明記など）
- どのスキルファイルを対象にするか

#### CLAUDE.mdに追記する場合

- プロジェクト全体に適用する制約・規則であれば CLAUDE.md に記載する

#### 承認の繰り返しが発生していた場合

承認が頻発した操作のパターンを特定し、以下のいずれかで対処する。

**許可リストへの追加**（読み取り専用・副作用のない操作が対象）
- `fewer-permission-prompts` スキルを使い、`settings.json` の allowlist に追加する
- `update-config` スキルで個別に許可ルールを追加する

**ユーティリティスクリプト化**（複数コマンドの組み合わせや副作用のある操作が対象）
- `scripts/` などにシェルスクリプトとして切り出す
- スクリプト単位で許可ルールに追加することで承認粒度を粗くできる

#### 次回から変えるフローがある場合

- サブエージェントへの指示の改善点を明記する

---

### ステップ4: アクションの実施

策定したアクションを即座に実施する。「次回から気をつける」で終わらせない。

- スキルの更新 → ファイルを編集する
- CLAUDE.mdの追記 → ファイルを編集する
- スキル新規作成が必要 → `writing-skills` スキルを参照する

---

## アウトプット形式

振り返り結果をユーザーに提示する際は以下の形式を使う。

```
## 振り返り

### 問題と原因

| 問題 | 原因カテゴリ | 根本原因 |
|---|---|---|
| ... | スキル不足 | ... |
| ... | エージェントの判断 | ... |

### 改善アクション

| アクション | 対象ファイル | 内容 |
|---|---|---|
| スキル更新 | .claude/skills/xxx.md | ... |
| CLAUDE.md追記 | CLAUDE.md | ... |
```

## チェックリスト

- [ ] 問題をすべて洗い出したか
- [ ] 各問題の根本原因を特定したか（「次は気をつける」で終わっていないか）
- [ ] 改善アクションが具体的で実施可能か
- [ ] アクションを実際に実施したか（ファイルを編集したか）
