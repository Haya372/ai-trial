# Retrospective スキル

## 目的

セッション中に発生した問題を振り返り、再発防止のための改善アクションを導き出す。
このスキルは問題の洗い出しから改善アクションの策定までを担う。実際のスキル更新・CLAUDE.md/AGENTS.mdへの追記などのファイル修正は `update-harness` スキルに引き継ぐ。

---

## ワークフロー

### ステップ1: 事象の洗い出し

会話を振り返り、以下の観点で問題を列挙する。

- エージェントが途中で止まって確認を求めた
- 同じ種類の操作に対して承認を繰り返し求められた
- 指示と異なる出力（言語・形式・内容）が生成された
- 手戻り・修正が発生した
- 想定より多くのターンを要した

---

### ステップ2: 根本原因の分類

各問題の原因を以下のカテゴリに分類する。

| カテゴリ | 意味 | 対策の方向性 |
|---|---|---|
| **ツールで防げる** | lint・静的解析・hookで自動検出できた | linter/hook設定を追加・強化する（最優先） |
| **スキル不足** | スキルに記載がなかった・曖昧だった | スキルを更新する |
| **スキル未参照** | スキルがあるのに参照されなかった | descriptionや呼び出し条件を改善する |
| **指示の曖昧さ** | ユーザーの指示が不明確だった | CLAUDE.mdに補足する・質問する |
| **エージェントの判断** | スキル・指示に関係なく発生した | スキルに明示的な禁止事項を追加する |
| **承認の繰り返し** | 同じ操作への承認が頻発した | 許可リストへの追加 or スクリプト化 |

> **原則**: ツールで防げる問題はツールで防ぐ。スキルへの注意書きは人間（エージェント）の記憶に依存するが、lint・hook・静的解析は忘れない。まず「自動化で解決できないか」を検討してからスキル更新に進む。

---

### ステップ3: 改善アクションの策定

各問題に対して、ステップ2で分類したカテゴリと「何をすべきか」を決める。**まず「ツールで防げるか」を検討する。**

具体的にどのファイルをどう直すかの判断基準（対象ファイルの選び方・修正方針）は `update-harness` スキルに委譲する。ここでは問題とカテゴリの対応を明確にし、次の「アウトプット形式」の表を埋められる状態にすればよい。

---

### ステップ4: アクションの実施

策定した改善アクションの実施は `update-harness` スキルに引き継ぐ。`retrospective` はステップ3で策定した「改善アクション」表を成果物として渡すところまでを担い、実際のファイル編集・ブランチ作成・PR作成は `update-harness` が行う。「次回から気をつける」で終わらせず、必ず `update-harness` に引き継いで実施させる。

---

## アウトプット形式

振り返り結果をユーザーに提示する際は以下の形式を使う。

```markdown
## 振り返り

### 問題と原因

| 問題 | 原因カテゴリ | 根本原因 |
|---|---|---|
| ... | スキル不足 | ... |
| ... | エージェントの判断 | ... |

### 改善アクション

| アクション | 対象ファイル | 内容 |
|---|---|---|
| スキル更新 | .claude/skills/xxx.md | ... |
| CLAUDE.md追記 | CLAUDE.md | ... |
```

## チェックリスト

- [ ] 問題をすべて洗い出したか
- [ ] 各問題の根本原因を特定したか（「次は気をつける」で終わっていないか）
- [ ] 改善アクションが具体的で実施可能か
- [ ] 改善アクションを `update-harness` スキルに引き継いだか
