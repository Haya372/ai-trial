# 仕様定義スキル

## 目的

PRDをもとに実装の詳細仕様を作成し、PDMと合意する。

```
PRD作成 → Issue作成 → [仕様定義 ← 今ここ] → 詳細設計 → TDD実装 → PRレビュー → マージ
```

## 手順

### ステップ 1: PRDを読む

```bash
cat docs/prd/PRD-XXX-[機能名].md
```

- ゴール・要件・非目標・制約・成功指標を把握する
- 不明点はユーザー（PDM）に確認する

### ステップ 2: 仕様書を作成する

`docs/spec/template.md` をコピーして `docs/spec/SPEC-XXX-[機能名].md` を作成する。

- SPEC番号は既存ファイルの連番とする
- ステータスは `作成中` で開始する
- PRD参照・Issue番号を必ず記入する
- 基本フロー・制約条件・エッジケース・受け入れ条件を埋める

### ステップ 3: PDMにレビュー・合意を依頼する

作成した仕様書の内容をユーザーに提示し、以下を確認する。

- 受け入れ条件はPRDのゴールを満たしているか
- スコープ外の定義に漏れがないか
- 制約条件・エッジケースに抜けがないか

フィードバックを受けたら仕様書を修正し、再確認を依頼する。

### ステップ 4: 合意後にステータスを更新する

PDMの合意が得られたら：

- ステータスを `PDM合意済` に更新する
- 合意日を記入する

### ステップ 5: 詳細設計フェーズへ引き継ぐ

合意済みの仕様書パスをユーザーに伝え、次のスキルを案内する。

- 次のスキル: `detailed-design`
- 引き継ぎ情報: 仕様書のパス・Issue番号

---

## 仕様変更時のルール

仕様変更が発生した場合は以下を必ず行う。

1. 仕様書を更新する（更新日を記入する）
2. 変更内容をPRの本文またはコメントに記録する
3. PDMに再確認・合意を得る

## 実装完了後のルール

実装のPRがマージされたら：

1. 仕様書のステータスを `アーカイブ` に更新する
2. PR番号を仕様書に記入する
